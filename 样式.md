# 状态面板 · 样式参考

**渲染出的状态面板**（显示在聊天消息下方的那张卡片）的完整 HTML/CSS 契约。这是一份查阅型参考；
上手教程见 [AUTHOR.md](AUTHOR.md)（English）/ [指南.md](指南.md)（中文）。English version:
[styles.md](styles.md)。

适用范围：本文档**只**涵盖面板 iframe，**不**涵盖设置窗口（字段 / 生成 / 样式 / 管理 标签页）。
下面的一切都来自引擎源码——`src/ui/styles.js`、`src/ui/render.js`、`src/ui/layoutgen.js`、
`src/core/constants.js`。

---

## 1. 一个面板是如何组装的

每个面板都在自己独立的**沙箱 iframe** 里渲染，每条消息一个。聊天样式进不来，你的样式也漏不出去。
iframe 文档由 `spBuildIframeSrcdoc`（`render.js`）按固定的源码顺序构建：

1. **提升的** `@import` —— 你写的任何 `@import` 都会被提到自己单独的 `<style>` 里放在最前
  （浏览器会静默忽略夹在样式表中间的 `@import`）。
2. **重置（Reset）** —— `*,*::before,*::after{box-sizing:border-box;margin:0;padding:0}` 以及
  `html,body{overflow:hidden}`。
3. **主题变量** —— 一段由角色卡主题旋钮计算得出的 `:root{ --sp-* }` 块
  （`spBuildThemeVarBlock`）。见 §3。
4. **全局外壳样式表** —— `SP_IFRAME_GLOBAL_CSS`：所有内置结构、按钮和徽章样式。见 §4。
5. **你的作用域化 CSS** —— 你的自定义 CSS，被改写到 `.sp-iframe-root` 之下（见 §7）。它在源码
  顺序中**排在最后，所以在同等特异性下会胜出**。

你的模板标记会被放进 body，包裹成这样：

```html
<body>
  <div class="sp-iframe-root">   <!-- your template goes here -->
    …your HTML…
  </div>
  <script>…engine bridge…</script>
</body>
```

`.sp-iframe-root` 是你能定位到的最外层元素。**默认没有背景**——你必须自己画一个表面，否则面板
文字会飘在光秃秃的聊天气泡上。

## 2. 模板令牌（插值）

`spInterpolateTemplate`（`render.js`）在 iframe 构建之前改写这些令牌。它先跑标签（label）过程，
再跑取值（value）过程。


| 令牌             | 会变成                                       | 说明                                            |
| ---------------- | ------------------------------------------ | ----------------------------------------------- |
| `{{field_name}}` | 该字段的**名称**（标签），已 HTML 转义        | 标签过程（S14）。先于取值运行。                   |
| `{field_name}`   | 该字段**存储的值**，已 HTML 转义              | 取值过程。用字段的精确键名。                      |
| `{sp_actions}`   | 🔄 重试 / ✏ 编辑 按钮行（见 §5）              | 保留令牌。展开为 `SP_DEFAULT_ACTIONS_HTML`。      |
| `{sp_badge}`     | 来源徽章（见 §6）                            | 保留令牌。没有来源时为空。                        |


**空值。** 当某字段的值为 `undefined`、`null` 或 `''` 时，`{field_name}` 展开为一个占位破折号，
而不是示例值：

```html
<span class="sp-ph sp-ph-dash" aria-hidden="true">—</span>
```

例外：在 `<style>` 块**内部**，同一个令牌会展开为**纯文本** `—`（不带 span），这样 CSS 永远不会
被破坏。这正是简易模式的进度条在没有数据时仍能工作的原理。

> 注意：单花括号 `{name}` = 值，双花括号 `{{name}}` = 标签。要**逐字节**匹配你字段的键名（包括
> 中文键名）。无法匹配的令牌会原样保留为字面文本。

## 3. CSS 自定义属性（`--sp-*`）

`spBuildThemeVarBlock` 总是在 `:root` 上输出全部十个变量，把每个为空的主题旋钮解析为一个由强调色
派生的默认值。**全局样式表用同样的回退（fallback）读取它们**，所以即便你在主题系统之外渲染标记，
这些默认值也依然适用。要设定你自己的值，就声明该变量（例如 `.sp-iframe-root{ --sp-accent:#e0a; }`），
或者直接在你的 CSS 里用 `var(--name)`。


| 属性                    | 默认值                                                   | 控制                                                   |
| ----------------------- | ------------------------------------------------------- | ------------------------------------------------------ |
| `--sp-accent`           | `#7c9cff`                                               | 基础强调色——进度条、药丸、按钮 + 徽章着色、标题         |
| `--sp-radius`           | `12px`                                                  | `.spg-card` 圆角半径                                   |
| `--sp-text-size`        | `13px`                                                  | `.spg-card` 基础字号                                   |
| `--sp-text-color`       | `rgba(255,255,255,.92)`                                 | `.spg-card` 文字颜色                                   |
| `--sp-title-color`      | 跟随 `--sp-accent`                                       | `.spg-title` 和 `.sp-badge` 文字                       |
| `--sp-border-color`     | `color-mix(in srgb, var(--sp-accent) 42%, transparent)` | `.spg-card` 边框                                       |
| `--sp-btn-color`        | `color-mix(in srgb, var(--sp-accent) 14%, transparent)` | 按钮背景                                              |
| `--sp-btn-border-color` | `color-mix(in srgb, var(--sp-accent) 40%, transparent)` | 按钮 + 折叠芯片边框                                    |
| `--sp-btn-text-color`   | `inherit`                                               | 按钮文字颜色                                          |
| `--sp-font`             | 系统 UI 字体栈                                            | `.spg-card` 字体                                       |


**每字段进度条变量（仅简易模式）。** 对每个数字字段，`layoutgen` 会在该行的 `.spg-fill` 上设一个
内联的 `--spg-v:{value}`，填充宽度为
`clamp(0%, calc((var(--spg-v) - min) / (max - min) * 100%), 100%)`。空值会让这个 `calc` 无效，
所以进度条会收缩到 0 宽度。这是布局生成的变量，不属于 `--sp-*` 主题 API。

## 4. 内置选择器（`SP_IFRAME_GLOBAL_CSS`）

引擎附带的每一个选择器。你自己的 CSS（作用域化到 `.sp-iframe-root` 之下）在同等特异性下会覆盖其中
任何一个，因为它在源码顺序里更靠后。

### 4a. 简易（Simple 模式）布局骨架

这些类由简易生成器（`spGenerateLayoutHtml`）输出。你也可以在高级模式里手动使用它们，以继承内置外观。


| 选择器                | 它所样式化的元素                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `.spg-card`           | 外层卡片——字体、文字颜色、`rgba(12,14,20,.88)` 背景（保持 ≥0.8 不透明，确保在聊天上方仍清晰）、`--sp-border-color` 边框、`--sp-radius`、`12px 14px` 内边距               |
| `.spg-head`           | 头部行——flex、`gap:8px`、`margin-bottom:8px`                                                                                   |
| `.spg-title`          | “状态”标题——`font-weight:650`、`--sp-title-color`                                                                              |
| `.spg-head .sp-badge` | 头部里的徽章——靠右固定（`margin-left:auto`）                                                                                   |
| `.spg-rows`           | 字段列表——纵向 flex 列，`gap:6px`                                                                                              |
| `.spg-row`            | 单个字段行——flex、`align-items:baseline`、`gap:10px`                                                                           |
| `.spg-row-num`        | 数字字段行修饰符——`align-items:center`                                                                                         |
| `.spg-label`          | 字段标签——`min-width:4.5em`、`opacity:.62`、`.92em`                                                                            |
| `.spg-value`          | 字段值单元格——伸展以填满、`overflow-wrap:anywhere`                                                                            |
| `.spg-value-num`      | 数字值单元格——`min-width:2.5em`、右对齐、`tabular-nums`                                                                        |
| `.spg-bar`            | 进度条轨道——`height:8px`、圆角、`rgba(255,255,255,.10)`                                                                        |
| `.spg-fill`           | 进度条填充——`--sp-accent` 背景、宽度过渡（由 `--spg-v` 驱动）                                                                  |
| `.spg-pill`           | 枚举值芯片——圆角、强调色混合的背景 + 边框                                                                                      |




### 4b. 操作按钮 + 折叠


| 选择器                                           | 它所样式化的元素                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------ |
| `.sp-actions-wrap`                               | 按钮行——flex、右对齐、`gap:8px`、`margin-top:10px`、可换行                |
| `.sp-btn-retry`                                  | 🔄 重试 按钮——`all:unset`、药丸形、`--sp-btn-*` 主题化                    |
| `.sp-btn-edit`                                   | ✏ 编辑 按钮——与 retry 同样的样式                                          |

| 选择器                  | 它所样式化的元素                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `.sp-badge`             | 来源徽章——等宽药丸形、`--sp-title-color` 文字、强调色混合的填充/边框                 |

## 5. `{sp_actions}` HTML + 交互

`{sp_actions}` 展开为 `SP_DEFAULT_ACTIONS_HTML`（`constants.js`）：

```html
<div class="sp-actions-wrap">
  <button type="button" class="sp-btn-retry" data-sp-action="retry" data-sp-label="🔄 重试">🔄 重试</button>
  <button type="button" class="sp-btn-edit"  data-sp-action="edit"  data-sp-label="✏ 编辑">✏ 编辑</button>
</div>
```

**数据属性**（由 iframe 内部桥接脚本 `SP_IFRAME_BRIDGE` 消费）：


| 属性                                | 位置               | 用途                                                   |
| ----------------------------------- | ------------------ | ------------------------------------------------------ |
| `data-sp-action="retry"` / `"edit"` | 两个按钮上          | 点击时向父级投递 `{type:'sp-action', action}`          |
| `data-sp-label`                     | 两个按钮上          | 待定状态清除后要恢复的标签                              |


**由桥接脚本驱动的运行时行为：**

- 当一次重试正在运行时，每个 `[data-sp-action="retry"]` 按钮都会 `disabled`，其文字变为
  `⏳ 生成中`；完成后恢复为 `data-sp-label`。
- `.sp-fold-toggle` 点击会在外层 `.sp-actions-fold` 上切换 `.sp-fold-open`；点击面板内其他地方会
  收起已展开的折叠。

你可以按类名自由地重设这些按钮的样式，但如果你想保留内置的 retry/edit 连线，就要保留
`data-sp-action` 属性和 `{sp_actions}` 令牌。

## 6. 徽章来源

`{sp_badge}`（`spBuildBadgeHtml`）把值的来源映射为一个徽章；不存在来源时产生空字符串。


| 来源      | 渲染出的 HTML                                        | 面向玩家的文字                  |
| --------- | --------------------------------------------------- | ------------------------------- |
| `markers` | `<span class="sp-badge">来自回复</span>`             | AI 在回复里写出来的             |
| `auto`    | `<span class="sp-badge">已生成</span>`               | 你按了 🔄 重试                   |
| `manual`  | `<span class="sp-badge">手动</span>`                 | 你手动编辑的（✏ 编辑）          |
| `error`   | `<span class="sp-badge sp-badge-error">生成失败</span>` | 一次重试失败了；旧值被保留      |

## 7. 你的自定义 CSS 是如何被作用域化的

`spScopeAuthorCss`（`styles.js`）改写你的 CSS，使它只能影响这一个面板。作用域前缀是
`.sp-iframe-root`（`SP_IFRAME_AUTHOR_SCOPE`）。它是一个分词器（tokenizer），不是完整的 CSS
解析器——嵌套（`&`）会被保留。


| 你写的                                 | 会变成                   | 含义                                            |
| -------------------------------------- | ------------------------ | ----------------------------------------------- |
| `:root`, `html`, `body`                | `.sp-iframe-root`        | 整个面板表面——在这里设 `background`             |
| `body.foo` / `html.foo`                | `.sp-iframe-root.foo`    | 开头的 `html`/`body` 就地替换                    |
| `.card`（任何普通选择器）              | `.sp-iframe-root .card`  | 作用域化为根的后代                              |
| `:host(...)`                           | `.sp-iframe-root`        | 影子 DOM 语法为兼容而映射                       |
| `:host-context(...)`                   | `.sp-iframe-root`        | 上下文被剥离                                    |
| `.sp-block-shell…` / `.sp-block-root…` | `.sp-iframe-root…`       | 旧前缀重新映射                                  |
| `&…`（嵌套）                           | 原样透传                 | 原生 CSS 嵌套可用                              |


**At 规则：**

- `@import` —— 被抽取并提升到 reset 之前的一个 `<style>` 里（无论如何都要把它写成你 `<style>` 的
  第一行；要验证网页字体是否加载，看 `fonts.gstatic.com` 请求，而不是控制台）。
- `@media`、`@supports`、`@container`、`@layer`、`@scope`、`@document` —— 其主体会被递归地重新
  作用域化（内部选择器也会加上 `.sp-iframe-root`）。
- `@keyframes`、`@font-face`、`@page`、`@counter-style`、`@property`、`@viewport`、
  `@font-feature-values` —— **不加作用域**地透传（它们的内容不是选择器）。

粘进 CSS 框里的 `<style>` 包裹标签会被自动剥除。

## 8. 基础默认值（reset）

`spIframeBaseCss` 在你的 CSS 运行之前，在根上设定中性基线：

```css
.sp-iframe-root{
  display:block; max-width:100%; overflow:visible; word-break:break-word;
  box-sizing:border-box; color:#2c3e50;
  font-family:system-ui,-apple-system,"Segoe UI",Roboto,Helvetica,Arial,sans-serif;
  font-size:14px; line-height:1.45; -webkit-text-fill-color:currentColor; color-scheme:light;
}
.sp-iframe-root *{ max-width:100%; box-sizing:border-box; }
```

实际后果：

- **务必自己设** `background` —— 默认没有。
- 如果你用 `.spg-card`，它自己的 `--sp-text-*` / `--sp-font` 值会覆盖这个基础颜色和字体。如果你写
  的是裸标记，在你覆盖之前，会应用基础的 `#2c3e50` 文字和 14px 系统字体。
- 目标宽度大约为 **320–380 像素**。永远不要用 `100vw` / `100vh` 或固定/绝对的整页定位——框会通过
  桥接脚本把自己的高度自动适配到内容。
